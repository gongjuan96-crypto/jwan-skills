# Jwan Event Visual Extension System

Turn one approved event key visual into a consistent family of event materials. This is a system-design Skill, not a collection of unrelated mockups.

## Typical outputs

- sign-in sheet
- staff / guest / media / attendee badges
- document folder
- seat nameplate
- agenda
- tri-fold brochure
- tote bag
- notebook
- wayfinding flags
- directional signs
- control-desk wrap
- other event touchpoints requested by the user

## Source lock

Treat the supplied key visual as the master system.

Preserve:
- event title
- logo / organizer hierarchy
- primary palette
- typography character
- key graphic motif
- spatial rhythm
- image treatment
- brand mood

Do not redesign the event identity unless explicitly requested.

## Adaptation rule

Adapt hierarchy to the physical object instead of forcing the full master poster onto every item.

For small or functional items, simplify intelligently:
- organizer blocks may be removed
- time / venue may be removed
- secondary copy may be removed
- decorative background may be cropped
- the key motif and title hierarchy should remain recognizable

Never invent a new logo, new event title, new sponsor, new date, or new venue.

## Material-specific behavior

### Badges
Differentiate categories clearly through label, controlled accent, or hierarchy while keeping one system.

### Agenda
Prioritize legibility, time sequence, and spacing. The agenda is information-first.

### Nameplate
Large readable name / role area. Keep branding secondary.

### Folder / notebook / tote
Reduce copy. Use the strongest motif and key title only.

### Signage
Direction must dominate. Brand graphics support navigation rather than compete with it.

### Tri-fold
Maintain panel logic and folding safety. Avoid placing critical text directly on fold lines.

## Mockup discipline

- One material per image when the user requests separate outputs.
- Do not combine every item into one contact sheet unless explicitly requested.
- Keep material scale and perspective believable.
- Show enough real-world context to explain usage, but do not let scene decoration overpower the designed object.
- When the user supplies an exact key visual, do not re-typeset its main title into a different style.

## Revision discipline

If the user asks to modify one material, do not drift the rest of the system.

Examples:
- "工作证改一下" -> update badge only.
- "删除主办单位和时间地址" -> remove those fields on the requested materials only.
- "只需要道旗和三种导视牌" -> output only those requested signage items.
- "不要门头" -> do not add a gateway or entrance structure.

## Hard avoid list

- unrelated styles between materials
- new color palette without request
- invented organizer names
- unreadable tiny information
- excessive copy on small items
- random logo placement
- one-size-fits-all poster pasted onto every object
- adding materials not requested

## Quality gate

Verify:
- all outputs belong to one visual system
- master title / motif remains recognizable
- information density matches the material
- functional text is readable
- no invented event facts
- requested material list is complete and only contains requested items
- small handwritten Jwan signature may appear on presentation mockups, but should not be treated as part of the client's actual production artwork unless requested
